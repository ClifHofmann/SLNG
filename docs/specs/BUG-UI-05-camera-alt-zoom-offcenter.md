# Bug & Polish: BUG-UI-05 (Camera Alt-Zoom Off-Center Focus Calculation)

## Context
The user reported a severe UX bug with the Alt-Zoom camera controls: *"wenn ich den zoom außerhalb der mitte beginne, springt das bult dahin als mittelpunkt [...] aber wenn ich dann scrolle also zoome, nimmt der den falschen fixpunkt zum zoomen"*. 
When initiating an Alt-Click on an object that is not in the center of the viewport, the camera acquires the object as a target, but scrolling the mouse wheel afterwards scales the zoom towards an incorrect spatial coordinate. Furthermore, the user noted that the initial focus change snaps instantly, which feels jarring.

## Requirements
1. **Fix Zoom Focus Math (Bug):**
   - Investigate the raycast logic in `AvatarController` or `CameraHUD` when Alt-LMB is pressed.
   - Ensure the exact 3D coordinate (hit point) generated by the off-center raycast is stored as the definitive `_orbitTarget`.
   - Verify that the mouse-wheel scroll logic calculates the zoom vector exactly along the line between the camera position and this `_orbitTarget`, rather than a screen-center ray or a stale vector.
2. **Implement Smooth Focus Gliding (Polish):**
   - Instead of instantly snapping the camera center to the new off-center target, implement a smooth interpolation (`Mathf.Lerp` or Godot `Tween`) over a short duration (e.g., 0.2s - 0.3s) so the camera "glides" into the new focus state.

## Acceptance Criteria
- [ ] Scrolling the mouse wheel after an off-center Alt-Click zooms flawlessly and precisely towards the clicked 3D point.
- [ ] Acquiring a new Alt-Click focus point smoothly pans the camera to center the point, rather than a hard teleport jump.
